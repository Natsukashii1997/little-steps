## 0. 一句话

首个切片做「观察闭环」：常浩第一次打开填名字和出生日期，在今天页看到硕之几个月几天，点「记一笔」记一条观察并挂到本月龄的观察点上，在今天页的「这个月记的」和成长页的「家里看到的」看到它，能改、能删，关掉再开还在；全程用权威包的壳、字体和弹层。

## 3. 数据与存储

### 3.1 数据模型（新建，和旧快照分开）

S1 新起一个本地存储键（建议 `baby-workbench-v5`），不读不写旧键 `little-steps-miniapp-family-v1`。结构：

```
baby        { name, birthDate }                              // 首次启动写入
content     按月龄的内容表（静态 JSON，随包发布，见 3.4）
records[]   { id, type: "observe", at, text, itemId?, seen: "seen"|"waiting",
              createdAt, updatedAt, deletedAt? }
```

- `itemId` 指向内容表里的观察点；没有就是自由观察。
- `seen: "waiting"` 必须有 `itemId`（审查 A2）。
- 删除是软删除（`deletedAt`），30 天后清理，沿用旧实现 `lib/retention.js` 的天数规则；S1 不做回收站界面。
- 每次写入后回读一次，和旧实现一样用 `setStorageSync`，写失败按规范 5.11 提示且不丢草稿。
- 成长页「家里看到的」= 本月龄观察点（左连接记录）＋ 本月自由观察；今天页那句话 = 本月最近一条 `seen` 的记录；月龄按出生日逐月推（审查 B13）。

S2 再加 `arrangements`（要安排的事）、`measures`、`concerns`（家里在留意）、`reviews`；S3 加 `media`。

### 3.2 持久化与备份

- 本地优先，和 ADR 0001 一致。S1 **不做云同步**。
- 因此 S1 的数据只在一部手机上。**S1 的验收和试用只用虚构数据**；真实记录从 S2（加上云端备份或同步）开始。常浩如果想在 S1 就记真实内容，要先知道这一点并自行决定。
- S2 时再定同步方式：复用旧 `familyApi` 的分区协议（ADR 0001），还是先只做「整包备份到云存储」。S1 的仓库层留一个 `Repository` 接口（load / save / export），同步作为适配器接在后面。

### 3.3 媒体：原片、小图、将来换到 NAS（只定接口，S3 实现）

- **原片**：选照片用 `wx.chooseMedia`，图片 `sizeType: ["original"]`，视频按返回的原文件；上传不重新压缩，保留拍摄时间。HEIC、实况照片和视频到底能不能拿到原文件，S3 开工第一件事在真机实测，实测结果写进验证记录。
- **小图**：照片用 `wx.compressImage` 另出一张约 400px 的方形小图（3 列格在 3 倍屏约 342px）；视频用 `chooseMedia` 返回的封面帧加时长。小图和原片分开存、分开取，相册格只拉小图。
- **接口**：`MediaStore { putOriginal(file) → id, putThumb(id, file), getThumbUrl(id), getOriginalUrl(id), listByMonth(month), remove(id) }`，外加一张清单：每个原片的 sha256、大小、拍摄时间、所属月龄。有了清单，「完整取回」才能核对。
- **后端**：先 `CloudBackend`（现有云开发环境的云存储，路径按月龄分目录），以后 `NasBackend`。NAS 接入推荐由 NAS 主动按清单从云端拉回家、核对哈希后再删云端，不让小程序直连家里的 NAS（小程序只能连登记过的 https 域名）。
- NAS 三题（接入前原片暂存哪、每月费用上限、NAS 型号与外网可达）在 S3 开工前问，S1、S2 不需要。

### 3.4 内容表（常浩已定由 Claude 起草、逐月确认）

- 先写成 Markdown（`docs/content/阶段内容表.md`）给常浩看，每个月龄一节、三类（要安排的、可以陪宝宝玩的、要留意的，其中观察点归在「可以陪宝宝玩的」旁边单列「这个月可能看到的」）；每条一句话，不下判断，不写疫苗名和剂量。
- 常浩确认一个月，脚本就把那个月转成 `content/stages.json` 进应用，并记下 Markdown 的哈希；没确认的月份不进应用，页面按空状态显示。
- S1 只需要 2–3 月龄和 3–4 月龄（硕之 2026-08-04 出生，现在 2 个月 19 天）。起草顺序：这两个月先，其余 10 个月在 S2 前陆续交。
- 页脚固定一句「内容整理自公开的儿童保健资料，以儿保医生的意见为准」。

### 3.5 字体（S1 的头号风险）

- 霞鹜文楷 Regular 与 Bold 做 GB2312 子集、WOFF 格式，放现有云存储，用 `wx.loadFontFace` 加载；加载前用系统字体，加载完切换。
- S1 第 1 批就实测：两个字体文件各多大、首开加载多久、系统字体下版面是否还能看。超过 4 MB 或 3 秒就换方案（只加载 Regular，标题用系统粗体），并记录。

## 5. 验证方法

1. 开工先记时间（`date '+%F %H:%M'`），记下要改文件的基线哈希。
2. 单元测试（node 直接跑）：月龄算法（含月末、闰年）、月龄窗口、记录挂条目与「在等必须有条目」、软删除与 30 天清理、今天页那句话的选取、内容表 JSON 校验。贴原样通过数与失败数。
3. 隔离运行：微信开发者工具游客隔离副本（和 10-13 一样），全部虚构数据，调试器 Errors 0；复现「保存失败」用断网。
4. 截图：390×844 和 320×568，每页每个状态（空、一条、多条、键盘态、出错态、系统字体态、文楷态）。放 `docs/handoff/slice-1/`，不进仓库。
5. T2 视觉复核：按 `visual-app-development-sop` Gate F，用 `$design-taste-frontend` 视角，对照标准屏、组件板和规范逐条；底栏文字按常浩决定的「今天｜这个月｜成长｜相册」复核，记为已同意的偏差。
6. 字体实测：文件大小、首开加载时长、切换前后版面各一张图。
7. 真机：用开发者工具「预览」二维码在常浩手机上跑一遍 S1 路径（不上传体验版）；常浩按下面清单验收。要先知道手机是 iPhone 还是安卓，两者键盘行为不同。
8. Gate C / D 对「观察」这一实体：新建、编辑、删除、重开、出错、空状态、320 宽、触控 44。

常浩的验收清单（真机上逐条点）：

- 第一次打开能填名字和出生日期，今天页显示正确的月龄；
- 记一条观察，挂到一个观察点，今天页那句话和「这个月记的」立刻出现；
- 成长页该观察点变成勾＋日期；
- 改一条、删一条；关掉小程序再开，数据还在；
- 断网保存，看到黑色圈叹号的提示，写的字还在，联网后「再试一次」成功；
- 字看着舒服、点得准。
