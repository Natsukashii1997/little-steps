## 代表性验收场景

### 场景 A：日常记录闭环（O-01）

- 初始数据：无当天便便和换尿布记录。
- 操作人：虚构测试成员“妈妈”。
- 操作步骤：分别快捷记录一次换尿布和一次便便，再编辑时间/状态，关闭并重开。
- 页面/系统结果：首页两张卡分别变为“今日 1 次”，最新时间正确，彼此不串数据。
- 刷新或跨角色证据：本地持久化、分区出站队列和合并逻辑已自动化验证；真实第二账号读取未验证。
- 拒绝/失败场景：连续快速点击只保存一次；不合法日期不写入。

### 场景 B：成长与健康一致（O-02）

- 初始数据：固定出生记录 2026-08-04、2.4 kg、48 cm。
- 操作人：任一已加入家庭的成员。
- 操作步骤：新增一条合法成长记录；勾选一针疫苗并将默认当天日期改为实际日期。
- 页面/系统结果：成长表和折线图同时出现同一条数据；疫苗显示已接种和修改后的日期。
- 刷新或跨角色证据：页面重载和派生图表已自动化验证；真实云端跨账号一致未验证。
- 拒绝/失败场景：同一天重复成长记录、出生日前或未来日期被拒绝；取消已接种先确认并可撤销。

### 场景 C：家庭同步与恢复（O-04、O-05）

- 初始数据：虚构家庭，无真实个人数据。
- 操作人：所有者、备用管理员、普通成员三种虚构身份。
- 操作步骤：创建家庭、加入成员、离线新增、联网同步、创建备份、修改数据、恢复旧备份。
- 页面/系统结果：权限按角色生效；重复操作只应用一次；恢复后数据回到目标版本且生成恢复前保护备份。
- 刷新或跨角色证据：内存 CloudBase 替身的 16 项家庭 API 和 9 项分区 API 测试通过，已包含停用成员的服务端访问拦截；真实微信云环境、两个账号和两台手机未验证。
- 拒绝/失败场景：第 7 人、非成员、旧版本、损坏备份均被拒绝且原数据不变。
